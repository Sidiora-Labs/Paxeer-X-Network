# D15: Sequencer receipt signing key

Status: decided

## Context
The sequencer returns signed receipts, so the key type and custody are fixed here. The existing verifier takes a pinned 32-byte ed25519 key (agent/crates/layerx-proof/src/receipt.rs:631).

## Options considered
| Option | Consequence |
|---|---|
| A: ed25519 key separate from the validator key, held by the sequencer, pinned in authority and /v1/settle | Reuses verify_sequencer_signature and every SDK verifier; rotation without a validator key change; one more secret |
| B: secp256k1 receipt key | EVM-native ecrecover; every verifier rewritten |
| C: the ed25519 node key itself | No extra secret; rotation tied to the node key |

## Decision
Option A is decided: receipts are signed with a dedicated ed25519 key, separate from the validator key, held by the sequencer and pinned in authority and /v1/settle.

## Consequences
- The receipt signature scheme is ed25519; SDK verifiers and the settle endpoint are reused unchanged (agent/crates/layerx-proof/src/receipt.rs:631).
- Key rotation follows its own procedure, independent of validator keys.
- Parity target: the existing verify_sequencer_signature tests.

## Affects
- Addresses: none
- Modules: sequencer, authority service, layerx-proof, agent SDK
