# D1: Kernel C modules and Rust program runtime inside the node

Status: decided

## Context
The kernel C modules (ledger, perps and spot, programs) and the Rust program runtime execute inside paxd, the single execution domain of Paxeer X Network. Every C module executes through an lxp_module_ctx execute function (src/modules/programs/registration.c:164), and programs run in the C module together with the Rust runtime (src/modules/programs/deploy.c:485). The CosmWasm message bridge is a separate path (node/wasmbinding/message_plugin.go:19), and the node already builds cgo code (wasm-runtime/version_cgo.go:1).

## Options considered
| Option | Consequence |
|---|---|
| A: host the existing C and the Rust runtime through cgo behind an lxp_module_ctx shim inside the keepers | Byte-exact parity; the existing C and Rust tests are reused; C execution joins consensus code, so determinism under OCC is proved by a spike |
| B: port each C module to Go keepers | Pure Go and OCC-friendly; parity only through a differential harness, with every test re-proved |

## Decision
Option A is decided: the C modules and the Rust program runtime are hosted through cgo behind an lxp_module_ctx shim inside the keepers. The decision is conditional on the C-in-consensus determinism spike meeting all five criteria: (1) the same block replayed through the shim on every validator build yields an identical app hash and identical per-transaction results; (2) OCC execution with forced aborts and re-execution yields the same state as strictly sequential execution; (3) no kernel in-memory state survives outside the committed KV store between transactions, or it is proved reset per transaction; (4) the existing C tests, Rust runtime tests and kernel replay goldens pass byte-exact through the shim; (5) no wall-clock, allocator-address, thread or floating-point dependence exists in any execute path reachable from a keeper. No alternative path is pre-committed.

## Consequences
- Every kernel keeper package is a cgo shim over the module execute function (src/modules/programs/registration.c:164).
- Program deploy and call run through the hosted C module and Rust runtime (src/modules/programs/deploy.c:485).
- Parity targets are the existing C unit tests, Rust runtime tests and kernel replay goldens, byte-exact.
- Hosting the kernel inside paxd removes the separate kernel domain, so no kernel-state view against a separate finalized root is required.

## Affects
- Addresses: every kernel-backed precompile
- Modules: layerxledger, layerxexchange, layerxprograms, the shared cgo host
