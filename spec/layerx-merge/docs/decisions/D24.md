# D24: Service dispute arbiter and escrow settlement

Status: decided

## Context
Service disputes open and resolve in the kernel service module (src/modules/service/lx_service_dispute.c:15, src/modules/service/lx_service_dispute.c:66). Resolution is accepted from either agreement party (src/modules/service/lx_service_dispute.c:85-90), and the ruling does not settle the linked escrow.

## Options considered
| Option | Consequence |
|---|---|
| A: kernel parity; the ruling is a record and the escrow settles through its own dispute path | Same goldens; a party can record its own ruling |
| B: an arbiter authority, with the linked escrow settled on the ruling | Semantic change; new vectors and a new authority |

## Decision
Option B is decided: service disputes gain an arbiter authority, resolution is accepted only from that arbiter, and the linked escrow settles on the ruling.

## Consequences
- Dispute resolution checks the arbiter authority in place of the party check (src/modules/service/lx_service_dispute.c:85-90).
- The ruling settles the linked escrow in the same execution (src/modules/service/lx_service_dispute.c:66).
- New error codes LXP_ERR_ARBITER_REQUIRED, LXP_ERR_UNAUTHORIZED_ARBITER and LXP_ERR_ESCROW_LINK_MISMATCH; their numeric values are set at activation rehearsal.
- New vectors for the arbiter path.

## Affects
- Addresses: 0x101B layerxpay
- Modules: kernel service module, kernel escrow module, layerxpay
