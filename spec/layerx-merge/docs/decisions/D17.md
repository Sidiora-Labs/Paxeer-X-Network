# D17: Client-facing contract

Status: decided

## Context
The agent-api major, the lx_* ingress names, same-nonce replacement, pending receipts on standard RPC and the status rung names are fixed for Paxeer X Network. The agent SDK calls lx_* methods today (agent/crates/layerx-sdk/src/rpc.rs:765), and the wallet SDK names its rungs instant, sealed and final (human/wallet/sdk/src/ladder.ts:4).

## Options considered
| Option | Consequence |
|---|---|
| A: compatibility (major 1 with dual-format fields, lx_* names kept and translated, replacement refused, signed receipts on a separate method, old rung names kept) | No client change; larger SDK surface; old rung names change meaning |
| B: clean break (major 2 with a 65-byte signature, PB1 replaced, cursor format, SettlementAnchored removed; lx_* switched off; rungs submitted, receipted, committed) | Middleware, x402 seller, CLI, SDK, gateway, explorer and wallet status UI move to major 2 |
| C: replacement with Superseded and pending receipts from eth_getTransactionReceipt | Fee bumping changes the same-key, same-activity rule; clients requiring blockHash change |

## Decision
Option B is decided: agent-api major 2, with rung names submitted, receipted and committed. The lx_* ingress switches off at activation. Replacement with Superseded and pending receipts from eth_getTransactionReceipt are not part of the contract.

## Consequences
- The agent SDK, gateway, explorer and wallet status UI move to major 2 (human/wallet/sdk/src/ladder.ts:4).
- Dual-format fields, PB1 and SettlementAnchored are removed.
- lx_* ingress methods end at activation (agent/crates/layerx-sdk/src/rpc.rs:765).
- Middleware, x402 seller, CLI and agent SDK adopt the 65-byte signature and the cursor format.
- The major-2 contract is published with the feature.

## Affects
- Addresses: none
- Modules: agent SDK, gateway, explorer, wallet, x402 seller, CLI
