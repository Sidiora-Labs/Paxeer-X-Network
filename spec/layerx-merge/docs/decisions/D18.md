# D18: Sequencer consensus scope

Status: decided

## Context
Receipt latency is independent of consensus, and the proposer executes and proposes the sequenced order. Without a fork, transactions arriving during consensus of height N wait up to one consensus round. Proposal blocks are built in the consensus block executor (consensus/internal/state/execution.go:101).

## Options considered
| Option | Consequence |
|---|---|
| A: one activation-height fork (BeginBlock of N+1 fed the votes of N-1, a new sequencer module with MsgSequenceBatch, a Leader() list rule) | Receipt latency independent of consensus; order provable on chain |
| B: no fork, no pipelining, proposer-address check only | Transactions arriving during consensus of N wait for its commit; order rests on trust in the operating nodes |
| C: autobahn producer with a one-member EVM shard | Reuses EvmProxy forwarding; autobahn is off and the switch is larger |

## Decision
Option A is decided: one activation-height fork in which BeginBlock of N+1 is fed the votes of N-1, a new sequencer module carries MsgSequenceBatch, and a Leader() list rule selects the sequencer. The activation height is set at activation rehearsal.

## Consequences
- The proposal builder takes the sequenced order (consensus/internal/state/execution.go:101).
- Order is provable on chain through MsgSequenceBatch.
- The sequencer node, the consensus binary and the activation height follow this fork.

## Affects
- Addresses: none
- Modules: consensus, sequencer, node
