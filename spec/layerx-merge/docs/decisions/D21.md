# D21: layerxAnchor 0x1014 reads after the fold

Status: decided

## Context
The layerxAnchor precompile is registered at 0x1014 (precompiles/layerxanchor/layerxanchor.go:65-66) and serves nine read methods beside its write methods. Its reads report anchor errors such as an unknown checkpoint (modules/layerxanchor/types/errors.go:12). Once the kernel runs inside paxd, finality is block height and commit, and the upgrade handler returns every posted guarantor bond (D4).

## Options considered
| Option | Consequence |
|---|---|
| A: freeze the store and keep the nine reads served permanently | No caller changes; a frozen store stays in state |
| B: serve the reads until bonds are returned, then delete the store; a retired executor remains | Smaller state; every reader moves in the same release |

## Decision
Option B is decided: writes return LXP_MODULE_DISABLED from the activation height; the nine reads stay served until every posted guarantor bond and open challenge deposit has been returned, then the layerxanchor store is deleted and the reads also return LXP_MODULE_DISABLED. The address stays registered with the retired executor.

## Consequences
- 0x1014 stays registered with a retired executor (precompiles/layerxanchor/layerxanchor.go:65-66).
- Read errors such as the unknown checkpoint remain until the store-delete step (modules/layerxanchor/types/errors.go:12).
- The store-delete step follows the bond return in the upgrade handler.

## Affects
- Addresses: 0x1014 layerxAnchor
- Modules: layerxanchor, upgrade handler
