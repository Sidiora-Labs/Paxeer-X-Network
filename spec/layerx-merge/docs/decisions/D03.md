# D3: Home of session keys and delegated authorities

Status: decided

## Context
The kernel defines eight authority kinds, including session keys and delegated capabilities (include/layerx/lxp_authority.h:11-19). All eight kinds are kept; the decision is where their grants live. The node already carries the authz module and its Authorization interface (sdk/x/authz/authorizations.go:11).

## Options considered
| Option | Consequence |
|---|---|
| A: sdk/x/authz with a LayerX-scope Authorization covering kernel and program calls | Standard module; one grant path for all authority kinds |
| B: a store inside layerxauth only | Self-contained; a non-standard store |
| C: the primary-key authority kind only at activation; program delegation through agent EVM keys | Delegated program authorities absent at activation |

## Decision
Option A is decided: grants for every kernel and program authority kind live in sdk/x/authz under a LayerX-scope Authorization, with an Accept rule per authority kind.

## Consequences
- Every kernel and program Msg authority check runs through one authz grant path (sdk/x/authz/authorizations.go:11).
- All eight authority kinds are kept, multisig and timelock scopes and program grants included (include/layerx/lxp_authority.h:12-19).
- Parity target: kernel authority-check outcomes per kind, each with a focused test.

## Affects
- Addresses: 0x101C layerxauth and every kernel-backed precompile
- Modules: authz, layerxauth
