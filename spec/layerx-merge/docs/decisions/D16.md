# D16: DID key rotation and the embedded-wallet ed25519 share

Status: deferred to the wallet feature

## Context
DID key rotation and the embedded-wallet ed25519 share need one model. The 0x1004 method set today is bindLayerX, unbindLayerX, getLayerXDid, getEvmAddrByLayerX, layerXBindNonce and getUnifiedAccount (precompiles/addr/addr.go:38-43). The choice governs application-level key handling, not chain execution.

## Options considered
| Option | Consequence |
|---|---|
| A: rotateOwner with DID-indexed accounts; keep the ed25519 share to sign bindLayerX and DID proofs | Identity survives rotation without a ceremony |
| B: unbind and rebind; retire the share after one bind | Later DID rotation needs a new ceremony |

## Decision
Deferred to the wallet feature: DID key rotation and the ed25519 share are an application-level matter decided with the wallet work. This feature adds no rotation method to 0x1004 and no task here depends on the choice.

## Consequences
- The 0x1004 method set is unchanged by this feature (precompiles/addr/addr.go:38-43).
- The wallet key ceremony is unchanged by this feature.

## Affects
- Addresses: 0x1004 addr
- Modules: evm binding keeper, embedded wallet
