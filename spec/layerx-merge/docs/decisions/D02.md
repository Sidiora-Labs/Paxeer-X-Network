# D2: Kernel account and margin model

Status: decided

## Context
Kernel accounts carry a sub-account kind and a parent account id (include/layerx/lxp_genesis.h:143-150). Perps margin accounts are owned per actor (src/modules/perps/lx_perps_dispatch.c:132). Paxeer X Network needs one model for DID sub-accounts and trading margin that bank, the explorer and ERC-20 pointers can read.

## Options considered
| Option | Consequence |
|---|---|
| A: derived bank addresses per DID and sub-account suffix; trading margin in the same namespace | Balances visible to bank, explorer and ERC-20 pointers; uniform model |
| B: one layerxledger balance store | Closer to the kernel layout; balances not visible to bank or pointers |
| C: exchange-store sub-ledger over one module bank account, for margin only | Simplest for trading; a second account model |

## Decision
Option A is decided: every kernel account maps to a bank address derived from its DID and sub-account suffix, and trading margin uses the same namespace.

## Consequences
- The exchange margin keeper holds margin on derived bank addresses, one per DID per market (src/modules/perps/lx_perps_dispatch.c:132).
- Explorer balance views read bank and ERC-20 pointers.
- The balance golden is an activation-height golden: the activation is a bring-up at the activation height; no account-state migration is required.
- Parity target: kernel sub-account parent and kind semantics (include/layerx/lxp_genesis.h:148-149).
- The derivation rule (DID plus sub-account suffix to bank address) carries its own focused test.

## Affects
- Addresses: 0x1001 bank, 0x1004 addr, 0x1015 layerxexchange
- Modules: bank, layerxledger, layerxexchange
