# D7: Time semantics under the sequencer cadence

Status: decided

## Context
Receipt timestamps, AI per-market height windows and the fee-token rate age all depend on block cadence. The kernel exposes a batch timestamp to modules (include/layerx/lxp_module.h:151). The fee-token rate age is a governance parameter (modules/evm/types/params.go:16) read by the evm keeper (modules/evm/keeper/params.go:310).

## Options considered
| Option | Consequence |
|---|---|
| A: timestamp fixed at pending-block open; re-tuned AI per-market height windows; rate age raised by governance | Matches the kernel batch timestamp; no fork and no codec change |
| B: per-receipt timestamp bounded by block time; AI windows and rate age switched to block time | Consensus validation of the bound and a hard fork; AI codec change |

## Decision
Option A is decided: the timestamp is fixed at pending-block open, AI per-market height windows are re-tuned for the new cadence, and KeyMaxFeeTokenRateAge is raised by governance. The new window and rate-age values are set at activation rehearsal.

## Consequences
- The pending-block builder fixes the timestamp at block open, replacing the kernel batch timestamp (include/layerx/lxp_module.h:151).
- A governance proposal raises KeyMaxFeeTokenRateAge (modules/evm/types/params.go:16).
- Oracle intake handles TIMESTAMP_REGRESSION for fresh observations, with a focused test.
- Frozen AI codecs stay intact; no fork is required for time semantics.

## Affects
- Addresses: 0x1015 layerxexchange (oracle intake), fee-token paths
- Modules: evm, layerxexchange, AI markets
