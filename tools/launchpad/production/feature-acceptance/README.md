# Feature acceptance policy plugin

This module supplies phase-one policy primitives to the serial qualification runner. It never marks tasks complete, changes capabilities, sends transactions, runs the product harness, or grants release approval. Every inventory feature starts `unqualified`. The 55 PF/OC declarations are not evidence that any product journey works.

`build_inventory.py` reads the frozen specification and generates `inventory.json`. `requirement_owner_lanes` is derived from every linked requirement's authoritative owner. `owner_lanes` is a curated behavioral integration assignment: for example PF01 creation directly coordinates L27/L39/L41, while the broad linked D09/D13 requirement coverage also retains other owners. Both are visible rather than substituting broad domain coverage for feature behavior. Inherited C/D dependencies retain their exact lineage identifiers. Legacy hosted-wallet dependency D03 is explicitly superseded by ordinary external Web3 wallet integration.

## Trusted caller contract

Import `policy.py` with `importlib.util.spec_from_file_location`; directory hyphen is intentional. Call `qualify(feature, gate, evidence, review, inventory=..., context=..., trust=..., artifact_root=..., dependencies=..., now=...)`. `Rejected` means fail closed and must be mapped to nonzero evidence failure by the serial runner. No unsupported gate is silently skipped. The root runner is not modified by this lane.

The coordinator must independently supply and pin:

* Context SHA256 digests `source`, `image`, `migration`, `api_schema`, `event_schema`, `registry`, `topology`, `policy`, `capability`, `inventory`, plus approved environment, implementation principals, exact admitted harness identity and fresh unpredictable per-invocation `run_id`. `inventory` equals `digest(inventory)`; source refers to actual candidate source, not an arbitrary hash supplied by an artifact. A final smoke gate has a 24-hour maximum; other feature evidence has seven days.
* Trust map keyed by signer identity. Each entry has public PEM key, enabled boolean, admitted roles, exact features and stable principal identity. Different keys belonging to the same principal cannot self-review. The coordinator owns admission, key revocation/rotation, uniqueness of principals, qualified reviewer status and implementation-owner identity completeness. Evidence never supplies a trust key.
* An artifact root owned exclusively by the immutable evidence store and a trusted current UTC clock. Verification rejects symlinks, hardlinks, traversal, missing or changed bytes and files over 64MiB. Capture streams should be split into bounded objects. The coordinator must prevent concurrent filesystem mutation while reading; this same-user filesystem is not an adversarial security boundary.
* Dependency booleans derived from separately verified current registry/vendor/device/service gates. Caller-provided booleans are not vendor evidence. Absent, false or non-boolean mandatory dependency blocks. Every inventory dependency names its remediation owner.

Evidence envelope has exact `payload`, `signer`, `signature` fields. Signature is canonical base64 Ed25519 over canonical sorted compact UTF8 JSON payload. The payload has exact version, feature, gate, bindings, environment, issued_at/expires_at integer UTC seconds, passed status, four separately registered scenarios, artifact descriptors, harness and run_id. Replay across invocations or harnesses fails despite identical candidate bytes.

Each scenario binds its expected assertion text digest from the pinned inventory and identifies a native result, authoritative state/receipt/provider artifact and user-path trace. Native result JSON binds scenario, run_id, candidate, assertion digest, positive test count, zero failures, zero skips and exit code zero. Every feature needs persisted state. Contract prerequisites additionally require receipt artifacts, vendor prerequisites provider artifacts, and physical-device prerequisites device artifacts. A responsive web trace cannot fulfill the native-device prerequisite. Artifact descriptors include exact SHA256/size/kind, immutable object version and retention at least 180 days beyond verification.

Review is a separately signed exact-scope envelope binding the evidence envelope hash, all artifact hashes, timestamps, disposition and resolved findings. Reviewer must differ from the producer and every implementation principal. Unknown/missing fields, duplicate JSON keys, nonfinite values, forged signatures, stale review, unresolved findings and incomplete scenarios fail closed.

`release_coverage` re-verifies all 55 signed feature bundles with the same trusted context. It does not accept boolean qualification claims, duplicate IDs or partial coverage. Even a complete feature-policy join returns `release_qualified: false`: all task graph, serial integration, capacity, security, recovery and final configuration gates remain the serial runner's obligation.

## Assurance boundary

Cryptographic checks prove provenance and integrity of admitted attestations. They cannot prove an admitted harness or reviewer is truthful, that a provider really delivered, or that an object store enforces immutable retention. Root must execute trusted harness adapters freshly and compare actual receipts/state/service/browser/device outputs before signing. The checked-in tests use real ephemeral Ed25519 keys and deliberately labeled policy-only artifacts; none is a product or capacity proof. No example production signing key is shipped.

Run `python3 -m unittest discover -s tools/launchpad/production/feature-acceptance/tests -v`. The suite creates private local ephemeral keys with installed OpenSSL, never contacts a service, and tests real signature verification plus rejection paths. OpenSSL absence or verifier timeout rejects evidence. Final immutable storage/WORM enforcement, secure key custody, real device/provider harnesses and root-runner registration remain integration prerequisites.

## Adversarial audit policy

Phase three adds `journey_policy.qualify_audited_feature` and the collector's `--phase 3` invocation. Each owner bundle includes a separately signed `audit` envelope. Existing evidence and journey contracts continue to apply. The audit reviewer must be the independent reviewer of the exact evidence envelope; the audit also binds the review envelope hash, every candidate digest, environment, invocation and expiry.

The trusted coordinator supplies `audit_authority` for all 55 feature identities. Each entry contains `required_traces`, `findings`, `blockers`, `redactions` and `private_artifact_root`. Required traces include the actual HAR and every expected service trace; the inventory comes from the admitted harness contract rather than offered artifact descriptors. Findings have `id`, `feature`, `severity`, `disposition`, `resolution_artifact`; unresolved critical/high findings or missing resolution artifacts reject. Mandatory blockers have `feature`, `owner`, `dependency`, `evidence`, `remediation`, `review_date`; any entry rejects acceptance. Audit signatures bind the complete independently supplied inventories so omission cannot be accepted by changing only an owner manifest.

`policy.audit_adversarial` first validates signed evidence, then copies only verified published artifacts to a temporary directory. It changes one HAR byte, removes the required HAR, evaluates a conflicting reviewer principal and advances the trusted clock by 30 days. Each case invokes the real policy and requires the expected rejection reason. Original evidence is preserved. These checks exercise evidence handling; they do not execute or establish product, provider, device, disaster recovery or capacity behavior.

`policy.redact_json_artifact` deterministically removes credentials from structured JSON/HAR headers, cookies, query parameters and JSON request bodies. It preserves transaction, block, chain, address, amount and candidate identities, and rejects retained credential patterns or absent authoritative identity. Each signed redaction entry identifies a private original artifact descriptor, published artifact path and identity digest. Audit validation verifies the private original's bytes and retention, recomputes redaction and compares exact published bytes. Private originals remain in the restricted evidence store. Unstructured credential-bearing inputs must be captured in a supported structured format; they cannot be silently accepted.

All Phase 3 results retain `release_qualified: false`. Actual owner execution, reviewer admission, complete trusted inventories, immutable storage and serial release gates remain independently required.
