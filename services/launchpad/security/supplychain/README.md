# Supply-chain authority primitives

`policy.admit_signed` is the public admission entry point. The controller must supply its independently trusted expected source/workflow/image/SBOM/repository/builder/run/ref and signing-public-key SHA256. Artifact fields cannot establish trust. Exact artifact bytes are verified with OpenSSL Ed25519 before parsing. Local test keys are generated and destroyed per test; no production keys are read.

The envelope binds six distinct required successful check IDs to the same source, immutable image, SBOM bytes, workflow, builder, repository and run. Issuance lifetime is at most24 hours. Forks, pull requests, stale evidence, scanner outages, omitted or malformed findings lists, reachable critical findings, expired or unapproved high exceptions fail closed. Exposure analysis is mandatory. A high exception lasts at most7 days. A builder-signed approver name never authorizes an exception: the controller must supply an independently approved canonical digest binding the finding, source, image, exact exception identity, controls and expiry. Production approval signatures and identity mapping remain controller obligations. Critical response operations must start within4 hours and mitigate within24 hours; this library does not prove staffing or response completion.

SBOM validation checks a normalized SPDX2.3 package inventory with explicit `kind` (go/javascript/os), versions and license conclusions. `NOASSERTION` is an explicit unknown, not a legal conclusion. A production standards-validating SPDX producer, complete transitive dependency/container inventory, immutable registry attachment and federated signing identity remain required. This primitive is not a claim that an SBOM generator or keyless transparency-log verifier is integrated.

CI removes privileged publication entirely while required tools, contracts source, scanner, signing identity and registry are unresolved. Pull requests receive only a read-only checkout, never registry/OIDC/signing credentials. The build job depends on all four check jobs and success(). Every external action is a full immutable revision (checkout v4.2.2 resolved upstream). Required Go1.26.4/Node24.16.0/pnpm9.15.0 match the qualified wave-zero baseline, superseding the earlier Go1.25 requirement. Missing runner tools fail closed. No external CI execution or registry publication was performed.

`build.py` requires independently reviewed immutable build/runtime images and a reviewed secret-excluding dockerignore. No digests are fabricated. The build image must contain Python3 and Go1.26.4. Dockerfile validates an explicit service/binary allowlist twice, verifies module sums, disables CGO, VCS metadata and build ID, uses trimpath and a fixed epoch. Media metadata is excluded pending its separate native-library image review. Runtime base must be separately approved as distroless; digest syntax alone cannot attest image contents. Nonroot USER is enforced in Dockerfile. Deployment read-only mounts, capability drops, seccomp, bounded tmpfs, resources and restricted egress are validated by `runtime`, then must be applied by D14. No actual container-confinement or two-clean-service-build proof is claimed here.

Run from repository root: `python3 -m unittest discover -s security/supplychain -p 'test_*.py' -v`.
