# Recovery measurement and release harness v4

The harness collects real read-only recovery metrics, actual Kubernetes resource allocations and PostgreSQL reconciliation snapshots. Its final evaluator consumes the existing D16 `kindle-shared-capture-v1` manifest. Component measurements prepare the lane; the shared 24-hour load and restore acceptance belongs to gate9.1. Every result keeps `capacity_qualified` and `monthly_availability_qualified` false. A local pass does not promote a release or activate recovery.

All input configuration and credential references are absolute owned mode0600 files. Configuration must match its independently admitted SHA256 and `config.schema.json`. It names the exact current source, interface, deployment, resource inventory and D16 candidate/interface/topology/generator bindings. Candidate source is reread through the existing production snapshot function. The only accepted runtime realm and environment are isolated recovery qualification. Missing providers, altered resources, absent data or failed measurements exit nonzero and produce ten explicit failed requirement results.

## Read-only measurement

Run `python3 deploy/production/recovery/phase4/release.py --mode collect --configuration <private-config> --configuration-sha256 <admitted-sha> --output-directory <fresh-owned-directory>`.

The collection configuration supplies `identity`, D16 `bindings`, `run_id`, SHA256-pinned `kubectl`/`psql` tools, `telemetry`, `allocation`, `postgres`, `dataset`, `duration_seconds` and `step_seconds`. Component duration is60–900 actual seconds; cadence is1–60 seconds and must divide the duration. No workload or results are fabricated. The existing D16 generators remain the load authority.

`telemetry` names the real Prometheus origin, application origin, explicit owned-loopback transport flag and a pinned private authority document. That document is version4 with exact diagnostic identity and bindings, and exactly ten metric mappings. Each requirement maps to an actual exporter `name` and admitted primary/recovery `zone`. The collector queries literal native selectors with service/environment/zone dimensions. Every raw query response is captured. Missing, ambiguous, warned, stale, future, nonfinite or fractional count/epoch series fail. Arbitrary PromQL and metric-name defaults are unavailable.

`allocation` supplies the actual context, namespace, namespace UID, private Kubeconfig and digest, exact pod/PVC UID sets and each container's admitted immutable image ID in `expected_images`. Before reading allocations, the collector verifies the live namespace UID and existing `kindle.io/environment=qualification` label. Pods must be ready and running; images must match; CPU/memory requests and limits must be positive and ordered. Volumes must be bound with actual capacity at least their requests. Quantities are parsed with exact decimal/binary arithmetic. Evidence captures resource fields and native response digests; pod environment/credential fields are not exported.

`postgres` uses the existing provider fields `service_file`, `service`, `expected_role`. The collector uses the real `phase2/reconciliation.sql` snapshot query under the authenticated database principal. The reviewed `dataset` document is version4 with realm, exact diagnostic identity, classification (`synthetic` or `reviewed-anonymized`), nonzero review/dataset digests and at least72 event hours. Both database snapshots are retained as observations; active-load before/after snapshots are not falsely asserted equal. Restoration comparisons instead use signed fixed-checkpoint scenario receipts.

The output contains exclusive private allocation/checkpoint JSON records, newline-terminated raw recovery metric records, a result and an artifact digest inventory. Failed or interrupted collection retains partial files and their hashes. Every record binds L44, run ID, identity and D16 bindings. Include the raw metric file and allocation records in the final D16 manifest as `native_provider` artifacts; their one-line JSON/NDJSON records satisfy the existing capture iterator. Do not change their bytes or invent a successful component result.

## Final capture evaluation

Run the same executable with `--mode evaluate` after the single integrated gate9.1 capture. The evaluation configuration supplies current identity/bindings, pinned D16 `capture`, metric `authority_sha256`, cadence, exactly ten signed `scenarios`, ten admitted `native_tool_sha256` values, an independent private `attestation_key` path/digest reference, pinned actual operating `budget` and actual connection/fanout/event burst windows.

The evaluator requires a fresh `final_shared` capture with L44 ownership, the frozen root workload ledger/mix, exact candidate/interface/topology/generator hashes and at least86400 actual seconds. It verifies every capture artifact through the existing D16 reader. Recovery metric coverage must include both endpoints and every cadence interval. It correlates real allocation records before and after the soak and each fault. The actual budget must be a `cost_budget` artifact of that immutable capture and satisfy the existing D16 storage/network/operating-budget evaluator.

Burst windows must come from the actual shared run. The connection surge lasts at least600 seconds with200000 connections, an equal authenticated/public split and mean five subscriptions; the fanout burst lasts at least600 seconds with1000000 delivered frames and400000000 payload bytes per second; the canonical-event burst lasts at least300 seconds with10000 accepted events per second. Native gateway interval records corroborate these values and enforce the existing queue, OOM, memory and generator resource bounds. A caller-declared window without matching native capture fails.

Each scenario envelope is `{payload,hmac_sha256}`. The payload contains version4, isolated realm, diagnostic identity, D16 bindings, run ID, requirement, start/end nanoseconds, fault, pinned native receipt, exact expected/actual version2 fixed-checkpoint reconciliations, input digest and empty limitations. Fault metadata names its actual fault ID, start/end and native control digest. The native receipt is the preserved version3 receipt from the real recovery executor, including executable/input/source identities, invocation times, zero exit code and the exact result enforced by `recovery.adversarial_scenario`. The envelope, native bytes, fixed checkpoint and actual D16 `FaultInterval` must agree. Missing or failed native executors from the earlier recovery phase remain blockers; this harness cannot synthesize their receipts.

All ten scenario results remain required: PITR marker restoration, measured RPO/RTO, stale write/ack denial, outbox republish and duplicate-effect rejection, broker-disk rebuild, corrupt-partition isolation and independent source,72-hour count/raw-amount/identity reconciliation, actual IAM/KMS denial and audit requester, missing-object accounting, and old-primary read-only return. Metric timelines additionally require WAL age below60 seconds, recovery elapsed at most1800 seconds, genuine rejection/replay/checksum/access-denial counter increases without resets, drained outbox, a fresh successful drill timestamp, observed missing-object recovery to zero and monotonic epoch activation. Invalid per-requirement input emits that requirement's failed result; missing shared prerequisites fail all ten.

The focused lane harness check is `python3 -m unittest discover -s deploy/production/recovery/phase4 -p test_release.py`. The real read-only provider test requires `RECOVERY_PHASE4_COLLECTION_CONFIG` and its admitted `RECOVERY_PHASE4_COLLECTION_CONFIG_SHA256`. Parser vectors are source checks; the provider test captures genuine allocations, metrics and database snapshots. No test starts a region fault, writes application state, creates workload, modifies Kubernetes resources or claims final capacity.

Serial integration registers the exact focused command and source inputs, provides the actual read-only namespace/database/Prometheus authority and reviewed dataset, attaches the emitted L44 records to D16 capture, and supplies independently signed native scenario results and actual cost authority. Final release acceptance remains blocked until those artifacts pass against the single integrated candidate.
